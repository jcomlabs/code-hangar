# Code Hangar v0.1.3 acceptance specification

Tracked document status: **STABLE SPECIFICATION — NOT CANDIDATE EVIDENCE**

This file defines the fixed gate inventory for v0.1.3. It must not be edited to
record a candidate commit, artifact hash, `PASS`, `HOLD` or machine-local path.
Doing that would change the commit being certified and create a provenance
cycle. Candidate-specific results are created only outside Git:

```powershell
$run = '.local\acceptance\v0.1.3\candidate\<new-run-id>'
$proof = '.local\acceptance\v0.1.3\release-proof\<new-proof-id>'
$localCi = '.local\acceptance\v0.1.3\local-ci\<new-local-ci-id>'
$stress = '.local\acceptance\v0.1.3\release-stress\<same-local-ci-id>'
$publication = '.local\acceptance\v0.1.3\publication-audit\<new-publication-id>'
pwsh -NoProfile -File scripts/acceptance-v013.ps1 -Initialize -EvidenceDir $run
# On the exact clean sanitized root, create the two independent AUTO-06 inputs.
# local-CI can claim the secret scan, but can never claim candidate topology.
# It creates $stress automatically from the $localCi leaf for private heavy-test logs.
pwsh -NoProfile -File scripts/local-ci.ps1 -AgentAutomation -SkipTauriBuild -EvidenceDir $localCi
$sourceTree = (git rev-parse 'HEAD^{tree}').Trim()
npm run audit:publication -- --source-tree $sourceTree --evidence-dir $publication
Copy-Item -LiteralPath "$localCi\LOCAL-CI-EVIDENCE.private.json" `
  -Destination "$run\shared-evidence\LOCAL-CI-EVIDENCE.private.json"
Copy-Item -LiteralPath "$publication\PUBLICATION-AUDIT.private.json" `
  -Destination "$run\shared-evidence\PUBLICATION-AUDIT.private.json"
# Run every gate. Complete its dedicated gate-proofs/<ID>.json and store only
# that gate's evidence below evidence/<ID>/. Create and validate the private
# release-artifact proof, then record its printed SHA-256 outside both dirs.
$proofSha = '<64-lowercase-hex independently recorded release-proof hash>'
pwsh -NoProfile -File scripts/acceptance-v013.ps1 -Finalize `
  -EvidenceDir $run -ReleaseArtifactProofDir $proof `
  -ExpectedReleaseArtifactProofSha256 $proofSha
$privateSha = '<64-lowercase-hex printed by Finalize and recorded out of band>'
pwsh -NoProfile -File scripts/acceptance-v013.ps1 -ValidateOnly `
  -EvidenceDir $run -ReleaseArtifactProofDir $proof `
  -ExpectedReleaseArtifactProofSha256 $proofSha `
  -ExpectedPrivateReportSha256 $privateSha
```

Initialization requires one exact clean source commit/tree. Finalization refuses
any non-`PASS` gate, wrong producer, missing/unbound evidence file, changed
specification, changed source identity or mismatched release-artifact proof. Each
of the 50 gates has a structured `codehangar/gate-proof/2` envelope bound to its
exact entry in `scripts/release-gate-contracts.json`: mode, producer id **and
schema**, required test IDs, shared evidence, lifecycle result IDs and typed
documents must match exactly. Automated gates accept no arbitrary per-gate
payload; they are validated against the canonical local-CI, strict
publication-candidate, packaging, release-proof and lifecycle outputs.
Supervised and owner gates require their
exact release-proof-bound attestation/report below their own `evidence/<ID>/`
subtree. Payload hashes may not be reused across gates; reusable evidence exists
only in the explicit shared registry. Thus 50 dummy `PASS` files — even one in
every subtree — seal zero gates. Finalization creates the schema-3 private
`ACCEPTANCE-EVIDENCE.private.json` once and refuses to overwrite it.

The private report may contain local paths, claims and owner evidence and must
remain outside Git and uploads. `scripts/checksums.ps1` revalidates its
independently recorded hash together with the private release proof and exports
the closed `codehangar/acceptance-evidence-public/1` projection as the staged
`ACCEPTANCE-EVIDENCE.json`. That projection contains only source/specification,
structured release/hash bindings and gate status/digests — never claim text,
notes, commands, output, local paths or secret-bearing payloads.
`RELEASE-MANIFEST.json` then binds the public projection hash. Historical v0.1.1
evidence remains evidence only for the old hashes it records; in particular it
cannot satisfy the v0.1.3 adversarial-inventory or progressive-session Test IDs.

The authoritative automated inputs are hash-bound outputs from
`local-ci.ps1 -AgentAutomation -SkipTauriBuild` and the separate
`publication-audit.mjs --candidate --source-tree` run on the exact clean public
root. `AUTO-06` requires `AUTO-06/secret-scan` from local-CI and
`AUTO-06/candidate-publication-audit` from the strict auditor. The validator
rejects a candidate claim issued by local-CI or a publication proof created by
worktree/history-only mode. The repository contains no GitHub Actions workflow
or Dependabot configuration; remote automation is neither required nor accepted
as an equivalent gate.

Canonical local-CI also runs `release-stress-v013.ps1` sequentially with Cargo
locked/offline, one build job and one test thread. It writes one immutable local
log per explicit `AUTO-03` stress Test ID plus a private manifest bound to the
same clean commit/tree under `$stress`. Local-CI emits those Test IDs only after
that fresh lane and every remaining canonical step pass; old v0.1.1 logs are not
promoted into v0.1.3 evidence.

The rule column is part of the stable contract. `REQUIRED` and `OWNER REQUIRED`
must both become `PASS` in the external result. `RELEASE BLOCKER` identifies a
currently known stop condition, not a weaker or waivable class.

| Gate | Rule | Required evidence |
|---|---|---|
| `SAFE-01` Source swapped after backup verification but before quarantine move | REQUIRED | Executor rejects identity/hash drift and the replacement survives |
| `SAFE-02` Source swapped after cross-volume copy but before unlink | REQUIRED | Exact bound source is removed or the operation fails; replacement survives |
| `SAFE-03` Held object swapped before permanent removal | REQUIRED | Exact handle/FileId and `object_archive/2` semantics are revalidated; drift blocks that topology group and the replacement survives |
| `SAFE-04` Hardlink or named stream appears after archive proof | REQUIRED | Same-handle pre/post disposition proof blocks the object; no success or reclaimed-space effect is recorded; independent objects may continue |

Also prove that a parent-proved pre-`ProveArmed` cancellation still sends authenticated `Cancel`, lets the guardian exit and permits a same-session retry. |
| `SAFE-06` Extended and legacy Windows disposition semantics | REQUIRED | A typed supervised attestation bound to the exact release proof records three distinct NTFS results: the Extended branch proves its mode-specific post-arm link count; the Legacy branch proves its own post-arm link count; and a failed cancel of delete-pending followed by abrupt parent termination physically preserves every raced byte. Local legacy-only or automated evidence cannot stand in for any of these three results. |

| `SAFE-09` Symlink and junction removal | REQUIRED | Only a proved name-surrogate link is unlinked; target remains untouched |
| `SAFE-10` Partial or failed move and opaque residual directory | REQUIRED | Project remains registered until no-follow residual proof is complete |
| `SAFE-11` Same-size and same-mtime replacement | REQUIRED | File identity/content evidence invalidates relationships and the plan |
| `SAFE-12` Plan requested during an active or incomplete scan | REQUIRED | Backend fails closed; no intermediate relationship state becomes ready |
| `SAFE-13` Backup, journal, copy, fsync, verification and recovery ordering | REQUIRED | Crash/fault-injection suite preserves at least one tracked recoverable copy |

## Exit rule

`ACCEPTANCE-EVIDENCE.private.json` may be sealed only when all 50 gates above are
`PASS` against one exact clean commit, every dedicated gate envelope and
gate-scoped evidence file is present and hash-bound, and the independently
hashed release-artifact proof revalidates. It then becomes a private input to
canonical checksum staging, not a claim that publication has already happened.

The public release is allowed only after that private report is revalidated by
its independent hash, its closed public projection is staged, the final
`SHA256SUMS` and `RELEASE-MANIFEST.json` are generated, the owner explicitly
authorizes upload, and every downloaded asset reproduces its local staged hash.
Until all of those later release-checklist steps pass, v0.1.3 remains a private
candidate.
